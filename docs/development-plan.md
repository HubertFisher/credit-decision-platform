# Credit Decision Platform — план реализации

## 1. Цель и подход

План определяет последовательность перехода от начального прототипа (учебные правила `+40/+20/+30`) к специализированному сервису принятия решений — **Credit Decision Engine** в соответствии с [техническим дизайном](design.md).

Каждый этап представляет собой логически завершённый шаг: чистая математика $\to$ версионированная кредитная политика $\to$ схема БД и персистентность $\to$ API и идемпотентность $\to$ эксплуатационная надёжность.

Существующие миграции Flyway `V1`–`V3` не изменяются. Все изменения схемы оформляются новыми миграциями `V4+`.

## 2. Дорожная карта этапов

| Этап | Название | Результат | Критерий готовности |
|---|---|---|---|
| **0** | **Дизайн и требования** | Актуализированная архитектура сервиса, контракты и финансовая модель | Документы `design.md`, `development-plan.md` и `README.md` согласованы и актуальны |
| **1** | **Финансовый калькулятор (чистый домен)** | Модуль расчёта дифференцированного кредита и платёжеспособности | Калькулятор независим от фреймворка; unit-тесты покрывают расчёт графика, копейки, формулу максимальной суммы |
| **2** | **Кредитная политика и принятие решений** | Модуль кредитной политики (`CreditPolicy`), правила лимитов по `creditScore`, оценка DTI | Детерминированное принятие решений (`APPROVED`, `COUNTER_OFFER`, `REJECTED`) с кодами причин; 100% покрытие тестами граничных значений |
| **3** | **Схема данных и персистентность (PostgreSQL)** | Новая миграция Flyway `V4`, JPA-сущность `CreditDecision`, репозиторий | Миграция корректно применяется поверх V1–V3; сущность сохраняет полный снимок решения, входных параметров и метрик; тесты на Testcontainers |
| **4** | **Сервис решений и транзакционная идемпотентность** | `CreditDecisionService` с обработкой повторных запросов (`requestId` / `Idempotency-Key`) | Повторный запрос возвращает сохранённый результат без дублирования записи; защита от гонок проверена тестом |
| **5** | **REST API v1 и валидация** | Контроллер `POST /api/v1/decisions`, `GET /api/v1/decisions/{id}`, пагинация, DTO и Problem Details | Валидация диапазонов, корректные HTTP-статусы (400 при невалидных данных, 200 при решении); DTO не раскрывают сущности БД |
| **6** | **Сквозная интеграция и документация API** | Полный цикл: запрос от основного бэка $\to$ расчёт $\to$ сохранение $\to$ ответ; примеры `requests.http` | Сквозные integration-тесты сценариев (полное одобрение, контр-оффер, отказ по баллам, отказ по DTI); `requests.http` обновлён |
| **7** | **Наблюдаемость и подготовка к интеграциям** | Метрики решений (Micrometer/Prometheus), структурированное логирование решений с traceId | Метрики распределения исходов (approved/counter/rejected), latency расчёта; готовность к опциональной публикации событий через Transactional Outbox / Kafka |

## 3. Детализация ближайших этапов

### Этап 1. Финансовый калькулятор дифференцированного кредита
- Создание чистых доменных моделей: `DifferentiatedScheduleCalculator`, `PaymentScheduleItem`, `CapacityCalculator`.
- Вход: сумма, срок, номинальная годовая ставка.
- Выход: график платежей, максимальный первый платёж, сумма переплаты по процентам.
- Обратный расчёт: вычисление максимально допустимой суммы кредита по доступному бюджету ежемесячного платежа.
- **Критерий готовности:** исчерпывающие unit-тесты на округление `HALF_EVEN`, точность до тиынов/копеек, проверку остатка долга в последнем месяце (ровно 0.00).

### Этап 2. Кредитная политика
- Модели: `CreditScoreLimits`, `DebtBurdenPolicy`, `CreditDecisionResult`.
- Определение правил:
  - Проверка минимального `creditScore` (отказ при $< 500$).
  - Лимиты суммы по диапазонам баллов (например, 500–549, 550–649, 650–749, 750–850).
  - Проверка DTI (допустимая доля совокупных платежей $\le 50\%$).
  - Определение статуса: `APPROVED`, `COUNTER_OFFER`, `REJECTED` с детализацией причин.
- **Критерий готовности:** тесты на каждый возможный исход и граничные значения (ровно на границе диапазона баллов, ровно при исчерпании бюджета).

### Этап 3. Хранение решений (Flyway V4 & JPA)
- Создание `V4__create_credit_decision_v2_table.sql`.
- Добавление индексов для поиска по `request_id`, а также для пагинации истории (`created_at DESC, id DESC`).
- Создание JPA сущности и репозитория.
- **Критерий готовности:** тесты Testcontainers с PostgreSQL 16, подтверждающие миграцию схемы и корректное сохранение/чтение снимка.
